# Aggiunto hook interno useEnvironmentInfo e allestita l'infrastruttura di test

## Contesto
L'utente voleva un unico hook per centralizzare ogni segnale ambientale di browser/device non già
catturato dagli hook esistenti, per ispezionare cosa è realisticamente disponibile prima di
decidere come (o se) persisterlo. Una sessione di ricerca ha catalogato ~70 segnali browser
recuperabili; una sessione di grill ha ristretto lo scope della v1 ai segnali che non richiedono
prompt di permesso, non sono deprecati e non sono tecniche di fingerprinting attivo — decisione
registrata in `docs/en/adr/0001-environment-info-signal-scope.md`. Durante l'implementazione con
TDD (obbligatorio per AGENTS.md §1.1 STEP 5), è emerso che il repo non aveva alcuna infrastruttura
di test nonostante AGENTS.md indichi Vitest + React Testing Library come stack, quindi questa
modifica include anche il relativo setup.

## Modifiche tecniche
```js
// Campi statici: calcolati una volta al mount, rispecchia il pattern già esistente di useDevice
const staticInfo = useMemo(() => getStaticEnvironmentInfo(), []);

// Campi dinamici: ognuno riletto solo sull'evento browser che può davvero farlo cambiare
useEffect(() => {
  const handleLanguageChange = () => setLocaleInfo(getLocaleInfo());
  window.addEventListener("languagechange", handleLanguageChange);
  return () => window.removeEventListener("languagechange", handleLanguageChange);
}, []);

// Ogni singola lettura logga se stessa individualmente, su richiesta esplicita dell'utente
const logField = (name, value) => {
  console.log(`[useEnvironmentInfo] ${name}:`, value);
  return value;
};
```
Due campi non hanno un evento di cambiamento nativo del browser e sono gestiti come casi speciali:
`timeZone` viene ricalcolato insieme a `language` su `languagechange` (non esiste un evento
dedicato), e `navigator.storage.estimate()` viene letto una volta al mount ed esposto tramite un
`refreshStorageEstimate()` manuale invece di essere sottoposto a polling.

## Motivazione
Le tecniche fingerprinting-grade (fingerprinting canvas/audio, renderer/vendor WebGL non
mascherati, enumerazione font, leak IP via WebRTC, `speechSynthesis.getVoices()`) e tutto ciò che
richiede un prompt di permesso sono stati esclusi anche quando alcuni tecnicamente non lo
richiederebbero — `thecore-auth` è una libreria pubblicata, e qualsiasi segnale raccolto di default
viene ereditato silenziosamente da ogni applicazione consumer. La persistenza
(indexedDB/localStorage/sessionStorage, configurabile) è stata deliberatamente esclusa da questa
iterazione: l'utente vuole prima vedere la forma reale dei dati via `console.log`, per poi decidere
lo storage in un follow-up una volta che l'uso reale avrà informato la scelta. Il setup
dell'infrastruttura di test non faceva parte della richiesta originale ma si è rivelato
inevitabile per rispettare lo step TDD obbligatorio di AGENTS.md — invece di saltare i test o
ridurre lo scope silenziosamente, è stato segnalato all'utente e aggiunto nello stesso branch.
