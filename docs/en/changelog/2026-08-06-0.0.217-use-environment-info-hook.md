# Gate useEnvironmentInfo logging behind config and export it publicly

## Context
Follow-up to the original `useEnvironmentInfo` hook (#31), which deliberately deferred two items to
"a follow-up issue": config-driven behavior via `public/config.json` and public export/
documentation. The hook had been temporarily wired into `src/App.jsx`
(`useEnvironmentInfo(); // TEMP: solo per validare i dati in console, vedi PR #32`) purely to
validate the shape of the logged data. The user asked to close this out: tie the existing per-field
`console.log` calls to a config flag that defaults to `false` and does not break anything if it is
missing from `config.json`, export the hook from `src/index.js`, and remove the temporary call from
`App.jsx`.

## Technical Changes
```js
// logField and every helper function it flows through now take `enabled` as
// their first argument instead of reading a module-level flag, since these
// helpers live outside the hook body and can't call useConfig() themselves.
const logField = (enabled, name, value) => {
    if (enabled) console.log(`[useEnvironmentInfo] ${name}:`, value);
    return value;
};

const useEnvironmentInfo = () => {
    const { environmentInfoLog } = useConfig();
    const loggingEnabled = Boolean(environmentInfoLog);
    // destructuring a missing config key yields `undefined`, and
    // Boolean(undefined) === false — a missing key behaves exactly like `false`
    // with no extra guard code needed.

    const staticInfo = useMemo(() => getStaticEnvironmentInfo(loggingEnabled), [loggingEnabled]);
    // ...every dynamic-field effect/state initializer threads loggingEnabled the same way
};
```

## Motivation
`logField` and the helper functions that call it (`getStaticEnvironmentInfo`, `getLocaleInfo`,
`getOrientation`, `getConnectionSnapshot`, `readMediaQuery`, `useMediaQueryPreference`) are defined
at module scope, outside the hook body, so they cannot call `useConfig()` themselves — the flag has
to be threaded through as a plain argument from the one place that *can* call it. A module-level
mutable flag was considered and rejected: it would leak state across every mounted instance of the
hook and make the tests order-dependent, whereas threading a value through arguments keeps each
render pure and independently testable. Relying on `Boolean(environmentInfoLog)` rather than an
explicit `key in config` check was deliberate: it means "missing key" and "key set to `false`"
collapse to the same code path automatically, satisfying the "don't break if it's not in
config.json" requirement without any special-cased branch. `useConfig()` throws if there is no
`ConfigProvider` ancestor, but that is pre-existing behavior shared by every other hook/context in
this library that reads config (e.g. `AuthProvider`) — consumers of this library are already
expected to wrap their app in `ConfigProvider`, so it introduces no new constraint.
