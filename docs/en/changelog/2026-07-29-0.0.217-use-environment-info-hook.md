# Add internal useEnvironmentInfo hook and set up the test harness

## Context
The user wanted a single hook to centralize every browser/device environment signal not already
captured by existing hooks, to inspect what's realistically available before deciding how (or
whether) to persist any of it. A research pass cataloged ~70 retrievable browser signals; a
grilling session narrowed the v1 scope down to signals that require no permission prompt, are not
deprecated, and are not active fingerprinting techniques — decision recorded in
`docs/en/adr/0001-environment-info-signal-scope.md`. While implementing with TDD (mandatory per
AGENTS.md §1.1 STEP 5), the repo turned out to have no test infrastructure at all despite AGENTS.md
naming Vitest + React Testing Library as the stack, so this change also sets that up.

## Technical Changes
```js
// Static fields: computed once per mount, mirrors the existing useDevice pattern
const staticInfo = useMemo(() => getStaticEnvironmentInfo(), []);

// Dynamic fields: each re-read only on the browser event that can actually change it
useEffect(() => {
  const handleLanguageChange = () => setLocaleInfo(getLocaleInfo());
  window.addEventListener("languagechange", handleLanguageChange);
  return () => window.removeEventListener("languagechange", handleLanguageChange);
}, []);

// Every single read logs itself individually, per the user's explicit request
const logField = (name, value) => {
  console.log(`[useEnvironmentInfo] ${name}:`, value);
  return value;
};
```
Two fields have no native browser change event and are handled as special cases: `timeZone` is
recomputed alongside `language` on `languagechange` (no dedicated event exists for it), and
`navigator.storage.estimate()` is read once at mount and exposed via a manual
`refreshStorageEstimate()` instead of being polled.

## Motivation
Fingerprinting-grade techniques (canvas/audio fingerprinting, WebGL unmasked renderer/vendor, font
enumeration, WebRTC IP leak, `speechSynthesis.getVoices()`) and anything requiring a permission
prompt were excluded even though some don't strictly need one — `thecore-auth` is a published
library, and any signal it collects by default is inherited silently by every consuming
application. Persistence (indexedDB/localStorage/sessionStorage, config-driven) was deliberately
left out of this iteration: the user wants to see the actual data shape via `console.log` first,
then decide storage in a follow-up once real usage informs the choice. The test-harness setup was
not part of the original request but became unavoidable to satisfy AGENTS.md's mandatory TDD step
— rather than skip tests or silently downscope, it was called out to the user and added as part of
this same branch.
